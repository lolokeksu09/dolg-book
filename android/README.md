# «Расчёт» · Android 0.5.0-beta.1 (нативная версия)

**Нативный Android UI, а не WebView:** экраны, навигация, формы, история и ввод долга строятся средствами Android Views. Данные находятся в приватной SQLite. Внутри APK нет HTML, JavaScript, WebView, JS-моста и файлов веб-сайта.

При каждом запуске появляется короткая нативная заставка. При первом запуске — фирменный экран Ventry о продукте «Расчёт», затем три интерактивных урока; после завершения или пропуска они не повторяются. Пустая книга открывает клиентов с кнопкой добавления. Нижние вкладки помещаются целиком.

Доступно: сводка по долгам и просрочке, поиск клиентов, создание и изменение контактов, новые долги и оплаты, частичное погашение, сроки возврата, отмена последней действующей операции с причиной, история и фильтры, резервная копия JSON/CSV, импорт ранее выгруженных JSON v1/v2 с проверкой и подтверждением замены. На планшетах от 720dp применяется боковая навигация. Онлайн-книга и материалы продвижения сайта не выводятся в интерфейсе APK. Общая серверная синхронизация — отдельный будущий этап, здесь не заявлена.

## Перенос данных из v0.2

Старая v0.2 хранит книгу в **WebView localStorage**, новая 0.5.0-beta.1 — в **SQLite**. Автоматического переноса нет.

Версия 0.5.0-beta.1 использует отдельный пакет `dev.ventry.raschet.nativev031` и **устанавливается рядом** со старой версией, не затирая её данные. В старой v0.2 выгрузите JSON. В новой 0.5.0-beta.1 откройте «Настройки → Восстановить из JSON» и выберите этот файл. Восстановление после подтверждения заменяет содержимое только новой SQLite-книги. Не удаляйте v0.2, пока не проверите перенесённые записи.

Удаление приложения/очистка данных уничтожит локальную SQLite-книгу. Автоматические копии Android и перенос на другое устройство отключены. JSON/CSV содержит имена, телефоны и суммы в открытом виде. Храните копии защищённо.

## Границы

Эта сборка — автономная локальная книга. Онлайн-синхронизация, сотрудники, покупки/подписки и защищённые автоматические копии не встроены. Физический запуск, визуальная и регрессионная проверка на устройстве требуют отдельной приёмки; успешная сборка APK её не заменяет.

## Контрольная проверка перед публичным выпуском

- Финансовый слой Android проверяется в реальном эмуляторе инструментальными тестами `LedgerStoreInstrumentedTest`, а не только тестами JS-прототипа. Они используют отдельный файл `raschet-qa-only.db` в sandbox целевого тестового приложения и не трогают `raschet-ledger.db` с пользовательскими данными.
- Создание JSON-копии: системный выбор документа, запись и закрытие потока, затем подтверждение сохранения и отметка даты последнего успешного JSON-экспорта. Отмена диалога не учитывается как успешная копия. После импорта другой книги дата последнего экспорта сбрасывается. При повороте во время выбора файла формат экспорта сохраняется.
- Эмуляторная проверка дополнительно проходит «Историю» и «Настройки», сохраняет скриншоты всех разделов.
- Подписанная стабильная версия не публикуется до проверки обновления и экспорта/импорта на физическом Android. Preview APK `dev.ventry.raschet.nativev031` и будущая release `dev.ventry.raschet` имеют **разные ID**: перенос между ними только через JSON.

## Подписанная APK: кандидат на релиз (отдельный workflow)

Workflow `.github/workflows/android-release-candidate.yml` проверяет release-вариант при PR и по ручному `workflow_dispatch` формирует **только при наличии секретов** подписанный кандидат APK и SHA-256. Он не публикует GitHub Release и не внедряет ключ в репозиторий.

После принятия изменений в `main` настройте GitHub Actions Secrets (ключи должны оставаться у владельца):

- `RASCHET_SIGNING_KEYSTORE_BASE64` — base64 содержимого постоянного Android keystore;
- `RASCHET_SIGNING_STORE_PASSWORD` — пароль keystore;
- `RASCHET_SIGNING_KEY_ALIAS` — alias ключа;
- `RASCHET_SIGNING_KEY_PASSWORD` — пароль ключа.

Первый подписанный выпуск использует пакет `dev.ventry.raschet`, отличный от preview `dev.ventry.raschet.nativev031`. При установке release-версии **она не подменяет тестовую**: сохраните JSON из preview, восстановите в release и сравните клиентов, суммы и историю; не удаляйте preview до проверки. Подпись всех будущих обновлений должна оставаться той же; утрата keystore нарушит обычное обновление APK. Все операции с копиями — на тестовых данных до настоящей миграции.

**Gate до публичного GitHub Release:** успешно закрытые Android Lint/assemble, инструментальные SQLite-тесты, эмульторный сценарий четырёх вкладок, ручная проверка импорта/экспорта/обновления на физическом устройстве и планшете. Публикацию не автоматизировать до подтверждения этих проверок.

## Первое знакомство: Ventry и Расчёт
На чистой установке сначала открывается фирменное представление Ventry (подлинная геометрия знака из `lolokeksu09/Ventry/site/favicon.svg`), с объяснением назначения автономного продукта «Расчёт». Кнопка «Посмотреть возможности» раскрывает конкретные функции, а «Как это работает» открывает три прежних интерактивных урока: долг, оплата и JSON-копия. Всего **4 экрана**. Уроки не пишут демонстрационные данные в SQLite; после завершения знакомство не повторяется. Для уже прошедших знакомство экран не показывается заново при обновлении. Приложение не объявляет серверную синхронизацию доступной.

## Обновление старой версии знакомства

Если человек уже завершил старые три упражнения в preview APK, после обновления он увидит **только новый экран Ventry**, с кнопкой «Открыть книгу». Повторять упражнения не нужно. После этого экран не показывается вновь. Если приложение установлено впервые, последовательность состоит из четырёх экранов. Переход определяется существующим `raschet_intro/completed` и новым `ventry_shown` в SharedPreferences; SQLite не очищается. Это не перенос данных между разными `applicationId`.

- На «Главной» появился блок «Контроль долгов»: просроченные суммы, возвраты в ближайшие 7 дней и список до трёх клиентов, требующих внимания. Все строки открывают реальную карточку клиента.
- В «Клиентах» появились фильтры «Все», «С долгом», «Просрочка», «Срок скоро», поиск и сортировка по имени/остатку. Параметры сохраняются при повороте экрана.
- В карточке клиента «Погасить весь остаток» **только открывает заполненную форму оплаты**. Без подтверждения записи нет. Сохраняется существующая защита от переплат.
- «Поделиться сводкой» открывает системное меню отправки Android; телефон клиента не включается в текст. Выбор приложения и адресата остаётся за пользователем, автоматических сообщений нет.
- `CollectionsInsights.java` вычисляет контроль сроков поверх действующих долгов, оплат и отмен без записи в SQLite. Погашения распределяются по старейшим долгам, как в `LedgerStore.overdue`.
- Отдельные инструментальные Android-тесты проверяют границу просрочки, +7 и +8 дней, отмену оплаты и фильтрацию. CI проверяет предзаполнение оплаты и фильтр просрочки.

Ограничение: нет фоновых уведомлений, массовых SMS или серверной синхронизации. Подписанный публичный релиз по-прежнему зависит от постоянного ключа и физической приёмки.

## Daily Operations · 0.5.0-beta.1

### Защищённые локальные точки восстановления

- `RecoveryVault` сохраняет **до четырёх** AES-256-GCM зашифрованных точек. Ключ генерирует Android Keystore. Перед импортом JSON и возвратом к точке сначала создаётся зашифрованная копия текущей книги; если она не создалась, операция замены SQLite не выполняется.
- Включаемая отдельно **«Автозащита после изменений»** запускает создание точки после подтверждённых форм записи. Она выключена по умолчанию. Работа происходит в отдельном потоке и зависит от состояния Android; отдельные короткие незавершённые записи при принудительном завершении процесса не гарантированы.
- Важное ограничение: эти точки **не переносятся на другое устройство**, удаляются с данными приложения и недоступны после удаления Keystore. Для защиты от утраты телефона обязательна внешняя JSON-копия, сохранённая в защищённом месте. JSON и CSV не шифруются приложением.

### Ежедневная работа

- **Черновики** незавершённых долгов и оплат отдельно для каждого клиента и типа операции. Приватные SharedPreferences, восстановление при повторном открытии и удаление после успешной записи. Черновики не шифруются отдельно; на общем устройстве рекомендуем системную блокировку.
- **Дубли клиентов:** подсказка при совпадении имени или номера телефона, без блокировки реальных однофамильцев.
- **PDF-выписка** клиента из существующих записей: даты, суммы, отмены, остаток и просрочка, постраничный экспорт через системный выбор файла. Для полной истории больше 2000 строк используйте CSV.
- **Локальные напоминания** о просрочках и приближающихся сроках: по умолчанию выключены; запускаются через Android JobScheduler примерно раз в сутки (не точное время). На Android 13+ пользователь отдельно разрешает уведомления. Имён, телефонов и сумм на экране блокировки нет; никаких SMS и сетевых запросов.
- **Широкий планшет:** от 1100dp список клиентов и выбранная карточка отображаются в двух независимых панелях. Для средних экранов сохраняется боковая навигация, для телефона — нижняя.
- **Производительность:** кэш расчёта долгов на время ввода поиска; история магазина выдаётся по 100 операций, история клиента — по 80 с кнопкой «Показать ещё».
- **Визуальная система:** знак Ventry в шапке приложения, интерактивные поверхности с Android ripple и более читаемые подписи навигации.

### Приёмка перед публичным выпуском

Новые Android Instrumentation тесты: `RecoveryVaultInstrumentedTest`, `LedgerDraftsInstrumentedTest`, `CustomerStatementPdfInstrumentedTest`, `DebtReminderServiceInstrumentedTest`. Тесты используют вымышленные данные и отдельные QA-базы. CI проверяет нативные сценарии на Android 15, включая широкий экран эмулятора. Уведомления в фоне, ручное восстановление JSON из стороннего поставщика файлов, сканирование доступности и реальное обновление APK **требуют физической проверки**.

Это **beta**, не подписанная публичная 1.0. Debug `applicationId` по-прежнему `dev.ventry.raschet.nativev031`; `versionCode=7`. При смене подписи или переходе на `dev.ventry.raschet` автоматического переноса данных нет — сначала экспортируйте JSON.


### Корректировка ошибок без удаления финансовой истории

В карточке клиента действие **«Исправить последнюю запись»** позволяет поменять сумму, комментарий и срок (только у долга), указав обязательную причину. `LedgerStore.correctLast` создаёт запись отмены со ссылкой на оригинал и новую правильную запись **в одной SQLite-транзакции**. Изменение не применяется, если получится переплата, будет нарушен порядок частичных погашений или не хватает места в истории. Исторические операции не удаляются; JSON v2 сохраняет проверяемую связь отмены. Исправление произвольной старой операции в этом выпуске не предусмотрено.

## Release candidate: постоянная подпись

PR собирает unsigned release для проверок, без доступа к ключу. Ветка разработки не является main: вместо недоступного workflow_dispatch используется push отдельного тега `raschet-v<versionName>-rc.<n>`. Только этот запуск собирает подписанный кандидат; публикация GitHub Release автоматом не происходит.

Необходимы четыре ранее предусмотренных Actions secrets `RASCHET_SIGNING_*` и публичная переменная Actions `RASCHET_SIGNING_CERT_SHA256` (64 hex-символа отпечатка сертификата). APK проверяется apksigner, совпадение сертификата, package name и versionName с тегом обязательны. Артефакт содержит SHA256SUMS, CERT_SHA256 и REVISION. Отдельная job без секретов запускает точно этот APK на Android 15 и проверяет обычные действия, переустановку с сохранением тестового остатка 800 ₽ и широкую компоновку. Это не тест обновления между разными версиями.

Первый стабильный пакет `dev.ventry.raschet` устанавливается отдельно от preview. Перед миграцией экспортируйте JSON из старой версии, затем импортируйте в release и сверяйте клиентов, операции и остатки. Старую установку не удаляйте до проверки. Постоянный ключ храните в защищённом месте вне Git и вне общедоступной папки телефона; сохраните отдельную защищённую копию ключа и пароля.


## 0.6.0-beta.1 — финансовый отчёт

- На главной открывается финансовый отчёт за сегодня, последние семь дней, текущий месяц или произвольный диапазон до 366 дней.
- Отчёт показывает остаток на начало и конец, записанные долги, оплаты, отмены обеих категорий, изменение задолженности, число операций и клиентов, детализацию по дням. Это движение долговой книги, не прибыль и не выручка магазина.
- Суммы рассчитываются целыми копейками; отмена относится к дате отменяющей операции, а не изменяет прошлые периоды. Даты определяются локальным часовым поясом устройства по записанному timestamp, включая импортированные смещения. История фильтруется независимо по типу и диапазону; отчёт может открыть операции выбранного периода.
- CSV содержит сводные суммы и дневные итоги, без имён, телефонов, комментариев и ID клиентов. Выбор файла явный; период сохраняется при пересоздании Activity. Данные формируются на момент записи файла. SQLite и JSON-формат не изменяются.
- Проверки: PeriodReportInstrumentedTest — отмены, границы, часовой пояс, диапазон, экспорт; Android smoke — открытие отчёта, сегодня, история и сброс дат. Физическая приёмка и постоянная подпись остаются обязательными.


## 0.7.0-beta.1 — защищённая клиентская книга

- REQ-DIR-01: рабочие клиенты, избранные и архив. Архивировать можно только клиента с нулевым остатком. Записи и история остаются в SQLite; при появлении ненулевого остатка клиент не скрывается. Архивные клиенты исключены из быстрого выбора; перед новой операцией требуется возврат из архива. Избранное/архив — локальные настройки текущей установки; после восстановления книги из JSON или точки восстановления они очищаются, не меняя историю.
- REQ-DIR-02: поиск с учётом е/ё, регистра и форматирования номера; поиск в выборе клиента при создании операции. Вывод списка клиентов порциями по 60, расчёт остатков не повторяется при каждом символе.
- REQ-PRIV-01: добровольная проверка системного PIN/пароля/графического ключа Android при открытии, ручной блокировке и возвращении после 60 секунд вне приложения. Включение/отключение требует системного подтверждения. При отмене разблокировки книга не открывается; требуется настроенный экран блокировки Android. Функция по умолчанию выключена. Это защита интерфейса, не отдельное шифрование SQLite и не разграничение ролей.
- REQ-PRIV-02: отдельная настройка FLAG_SECURE для блокирования снимков экрана и превью недавних приложений; при защите входа она включается автоматически. Ограничения платформы и физическая проверка системного диалога остаются обязательными.
- REQ-COMP-01: applicationId и формат JSON/SQLite не изменены; versionCode=9. Подпись и перенос из preview всё ещё отдельные обязательные условия Stable.
- Проверки: ClientDirectoryInstrumentedTest проверяет отсутствие скрытых долгов, обратимость архива, избранное, нормализацию поиска и границу тайм-аута. Smoke проверяет путь архивирования и возвращения клиента и прежний остаток 800 ₽. Реальная авторизация на устройстве с PIN требует отдельной приёмки; тест тайм-аута не доказывает работу системной авторизации.


## 0.8.0-beta.1 — покупки в долг

- В главной и карточке клиента доступно действие «Долг по товарам». Можно указать от 1 до 8 позиций, название, количество до 1000 с точностью до 0,001, цену в рублях, общую скидку, срок возврата и комментарий. Количество умножается на цену в копейках, результат позиции округляется HALF_UP до копейки; итог равен сумме позиций минус скидка. Итог должен быть положительным. Старое добавление долга одной суммой сохранено.
- Состав хранится как неизменяемый снимок внутри записи SQLite. История позволяет открыть позиции; состав включён в выписку PDF и в отдельный столбец полного CSV. Отмена сохраняет оригинальный состав; при исправлении комментария или срока состав переносится в новую запись. Поиск и фильтр срочности, кнопки оплаты и планирования, переход в карточку с возвратом в очередь. План следующего контакта (дата и комментарий) не меняет договорный срок или финансовую операцию. План скрывается для погашенных клиентов, при полном погашении через форму очищается. Настройка локальная, не экспортируется в JSON, очищается при восстановлении; автоматических SMS или новых уведомлений нет. В книге убрана повторная секция контроля, отчёт остаётся доступен. Схема SQLite, JSON, фирменные ресурсы неизменны. Проверки очереди и UI добавлены; визуальная приёмка нового SHA обязательна.


## 0.24.0-beta.1 — обещания оплаты

В плане возврата необязательно указать обещанную сумму. Платежи, внесённые после последнего ID операции при создании обещания, засчитываются в прогресс только если не отменены; срок оценивается по локальной дате действующей записи оплаты. Это проекция учётных записей, а не доказательство фактического контакта или банковского поступления. Исправленные платежи учитываются по дате и порядку новой записи. Изменение обещанной суммы начинает новый отсчёт, изменение даты/комментария при той же сумме сохраняет его. Одно текущее обещание на клиента, включая выполненное; полное погашение не стирает обещание, обычный план контакта очищается. Быстрая кнопка в форме оплаты подставляет остаток обещания в пределах текущего долга, не проводит оплату автоматически. Настройка локальная, не экспортируется и удаляется при восстановлении. Исправлен compile error 0.23: LinearLayout.setMinimumHeight. Схема и формат резервной копии не меняются.


## 0.24.1-beta.1 — согласованность черновиков и обещаний

Черновики долга и оплаты в карточке клиента сохраняют UUID и дату записи; прежний локальный формат черновиков читается с миграцией при открытии. Повторный UUID не может провести вторую операцию. После восстановления книги удаляются все черновики (включая карточки клиентов). При явном полном погашении существующий черновик сохраняет свою сумму и предупреждение, а не смешивается с новым значением. В обещании можно явно начать новый отсчёт с той же суммой. При закрытии быстрой формы обновляется видимость незавершённой записи. Проверка предельного остатка видна до сохранения. База SQLite/JSON и правила расчёта прежние. Добавлены тесты повторной записи, даты и восстановления формы.


## 0.25.0-beta.1 — карточка клиента и приём оплаты

История клиента группируется по календарным датам. Фильтры: все, непогашенные, долги, оплаты, отмены (отменённая запись и её отмена). Остаток каждой записи рассчитывается существующим FIFO по всей истории клиента до фильтрации; погашенная запись не скрывается из полной истории. Черновики видны в карточке и открывают исходную форму; сохранённые операции не предлагаются повторно. Список выбора клиента при оплате — компактные строки с именем, телефоном, остатком и просрочкой. Формат SQLite/JSON, идентификаторы и правила записи не меняются.


## 0.26.0-beta.1 — дата получения оплаты

В форме оплаты выбирается фактическая дата, по умолчанию сегодня. В раскрытом дне журнала оплат доступна запись за этот день. Черновик сохраняет выбранную дату. Для прошлой даты максимальная сумма ограничена минимальным остатком на конец дня от выбранной даты до сегодняшнего дня с учётом дат отмен; будущие даты запрещены. Дополнительно действует обычная проверка текущего остатка и UUID. После сохранения из книги раскрывается выбранный день, включая старые даты. Финансовый отчёт использует дату получения; FIFO и обещания по-прежнему используют порядок внесения (дата учитывается для срока обещания). Коррекция/отмена сохраняют действующий контракт. SQLite/JSON не меняются.


## 0.27.0-beta.1 — список клиентов

Фильтр «Без долга» включает клиентов с нулевым остатком (включая контакты без операций). Сортировка «последние операции» по порядку внесения, включая отмены; контакты без записей внизу, при равенстве — имя и ID. Выбор фильтра/сортировки сохраняется при пересоздании Activity. Компактная строка числа найденных клиентов и общей задолженности всех результатов, не только отображённой страницы. Пустое состояние отличает пустой архив/избранное от пустого результата фильтра. В списке клиентов, выборе получателя оплаты, книге и истории форматированные российские 11-значные номера с 8/+7 совпадают; неполный поиск остаётся по подстроке цифр. База, UUID, финансовые операции и JSON не изменяются.

Та же нормализация применяется в подсказках новой записи и при предупреждении о совпадающем телефоне. Совпадение не объединяет клиентов автоматически; отдельный клиент по-прежнему требует явного подтверждения.
