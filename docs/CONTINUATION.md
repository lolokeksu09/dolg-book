## Админка подписок

- Проверено на локальном HTTP-сервере с имитатором поставщика токенов. Владелец продукта находит магазин по номеру и подтверждает оплату. Сервер сохраняет срок и историю, повтор подтверждения не продлевает подписку.
- Покупатель получает номер своей книги через `GET /shops`. Сервер проверяет активность подписки при добавлении клиентов и операций и сохраняет чтение после окончания срока.
- Для запуска с реальными магазинами остаются подключение реального провайдера входа, настройка идентификатора оператора `LEDGER_ADMIN_SUBJECT`, подключение Android-клиента и проверка на тестовом окружении перед публикацией.

## Вход и первая общая книга

- Готовы вход через Keycloak и общая книга с подключённым API. Проверка `npm test` — 21/21. В локальном браузере с имитатором провайдера пройден путь от создания магазина покупателем до активации оператором и частичной оплаты. На локальном Keycloak 26.8.2 по TLS дополнительно проверены discovery, introspection настоящих токенов, аудитория, подтверждённая почта и разграничение доступа к активации. Из 350,50 ₽ долга после оплаты 100 ₽ осталось 250,50 ₽.
- Модуль Android находится в каталоге [android](../android/README.md) публичного `dolg-book`. Сборка с HTTPS origin открывает общую книгу в браузере и устанавливается рядом с автономной книгой. Перенос локальных данных не реализован.
- Остаётся настроить реальный realm и два аккаунта для испытания, внешний HTTPS origin и одну реплику с постоянной базой. После развёртывания повторить проверку с реальным провайдером и собрать APK с фактическим адресом по инструкции в репозитории Android.

Android-модуль проверен локально на Gradle 8.11.1, JDK 17 и Android SDK 35. `lintDebug assembleDebug` выполнены успешно. `apksigner verify` подтвердил отладочную подпись, `aapt dump badging` — пакет `dev.ventry.raschet.debug` и minSdk 33. Сборка использует тестовую конфигурацию с отключённой кнопкой открытия. Запуск на телефоне, релизная подпись и внешний сервер остаются для приёмки.
