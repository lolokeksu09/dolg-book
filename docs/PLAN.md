## Зависимые этапы

1. Документы и сохранение исходного состояния. Критерий: актуальный реестр, инструкции и код доступны в репозитории; доказательство — GitHub commit и проверка его содержимого.
2. Выбрать серверный стек и схему хранения с владельцами, магазинами, участниками и журналом операций; описать переход из локальных копий. Критерий: воспроизводимая изолированная среда.
3. Реализовать сквозной сценарий: владелец создаёт магазин, продавец добавляет долг, владелец видит его на другом устройстве. Проверить изоляцию и запрещённые действия.
4. Проверить синхронизацию при потере сети, повторе запросов, конкурентных изменениях и отказах, без потери или удвоения сумм.
5. Добавить резервирование и испытать восстановление в отдельной среде; сверить данные до и после. Переход действующих данных только с обратимым планом и копией.
6. Пилот с магазинами и проверка готовности платить; после фактических результатов подготовить тариф и интеграцию платежей.

## Проверки и границы

Для документации — L1 по проверяемым фактам и ссылкам. Для прав, финансовых записей и синхронизации обязательны положительные и отрицательные L2/L3; для миграции — восстановление. L4/L5 не считаются пройденными без приёмки и проверки конкретной поставленной версии. На публичном GitHub использовать только фиктивные данные. Не выдавать прототип за готовый платный сервис.

## Ход работы: серверное ядро

Создана изолированная модель на Node.js 24 + SQLite: магазины, роли, журнал, идемпотентные операции и ручная копия. Тест `node --test tests/*.test.js` — 8/8 PASS. REQ-02/03/04/05 частично покрыты только на уровне доменного слоя: не подключены проверенная идентификация, сеть, UI, офлайн-очередь, автоматическое резервирование и восстановление в production. Окончательный серверный стек и механизм идентификации не утверждены; SQLite используется для локального прототипа.
