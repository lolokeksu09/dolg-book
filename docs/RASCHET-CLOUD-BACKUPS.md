# Cloud backup Android staging (Ventry #89)

> Текущий статус и порядок: [CONTINUATION](https://github.com/lolokeksu09/dolg-book/blob/main/docs/CONTINUATION.md), [единый план Ventry](https://github.com/lolokeksu09/Ventry/blob/main/docs/ECOSYSTEM-STATUS.md). Ниже — контракт и исторические доказательства; старые статусы не переопределяют текущий снимок.
Public licensed build only: Settings → Cloud backups. Manual list, three slots, explicit upload/replacement and restore with password and confirmation. No background uploads, password persistence, new Android permissions or plaintext temporary files. Password exact UTF-8 (no normalization, no trim), 12–128 UTF-16 code units, valid surrogate pairs, not all whitespace. Use a high-entropy recovery passphrase; server cannot reset it. VRB1 AES-256-GCM, random 16-byte salt/12-byte nonce, PBKDF2-HMAC-SHA256 600000 rounds, 32-byte authenticated header and 16-byte tag. Python hashlib/AESGCM vector checked independently; unit tests verify known bytes, round trip and tampering/wrong passphrase. Bound encrypted blob 16 MiB, plaintext 16 MiB minus 48 bytes, memory-only with best-effort byte array wiping (JVM/crypto provider copies cannot guarantee zeroization). Server metadata hash + length + version validated before authenticated decryption. Network fixed public HTTPS origin, system TLS, no redirects; existing refresh credential remains internal, pending activation blocks calls. No retry on ambiguous write until refreshed list; CAS protects old slot. No cloud requests in ordinary offline and private staging builds.

Cloud write/restore shares the BookViewModel serialized command path; actual JSON export includes supported v2–v5, restoration goes through existing strict atomic importer and creates an encrypted rollback point. No new DB schema or release version. Restore confirmation is required before replacing the local book; password dialog uses secure window and no saved state. Current device still needs valid server binding for expired read; new-device transfer after expiry requires separate policy. Server 007 and public ingress are not yet enabled. On this PR tests only, physical device/API end-to-end remains blocked until server migration and routing, automated backups and recovery-key UX are separate tasks. Existing signed 0.31 candidate is not modified.

## Automatic backups — opt-in candidate
Explicit first upload to slot 3 (confirmation including replacement if occupied); slots 1/2 remain manual. Disable preserves all server data and removes device-wrapped passphrase/key. While enabled, manual replacement of slot 3 is blocked; restore remains available. Android JobScheduler persisted periodic 24h, unmetered network and battery-not-low, no exact time guarantee; only public licensed manifest declares the service/ACCESS_NETWORK_STATE. No new server API or schema. The recovery password must be separately recorded; automation uses an Android Keystore AES-GCM-wrapped local AtomicFile in noBackupFilesDir. JVM strings/provider copies are not reliably zeroizable. No plaintext temporary files, no logs or notifications containing secrets. The local encrypted record pins the credential fingerprint and last acknowledged slot version and plaintext digest; use the same captured credential for list/put. Any remote version mismatch stops automation without overwrite; unchanged snapshot skips upload. CAS prevents stale writes. Uncertain upload completion is not blindly retried; next list must match last acknowledged version or stop. Disable serializes with the running job: an already-started upload may finish before disable completes. A job stopped by Android does not start a new upload; an already-transmitting request may still complete. Snapshot uses existing transactional JSON writer; worker never restores or edits financial data. Local JSON, restore points and manual copies remain independent. Job and vault runtime acceptance on a licensed Android phone, expiry, reboot, credential replacement, disable while uploading, actual backup restore and policy unit tests are gates. No commercial release in this PR.
