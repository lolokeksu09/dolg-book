# Расчёт Android — ТЗ 0.3.2: запуск, первое знакомство, UX-полировка

**Основание:** пять скриншотов с Legion Y70 (23 ноября 2026), текущая нативная версия 0.3.1. Исходный код: `android/app/src/main/java/dev/ventry/raschet/MainActivity.java`; база: `LedgerStore.java`. Изменения выполняются в существующей Android-ветке и PR #6.

## Цель и границы
Создать последовательное первое впечатление от готовой **долговой книги**, а не веб-панели: короткая брендовая заставка на **каждом холодном открытии**; **три шага знакомства только один раз**; исправленные нижняя навигация и пустые состояния; компактный обзор и нативный переключатель крупного текста.

**Не менять:** БД SQLite, ID существующего пакета нативного предварительного APK (`dev.ventry.raschet.nativev031`), подпись, логику сумм в копейках, экспорт/импорт JSON/CSV, защиту от переплаты/отмены, четыре раздела и палитру бренда. Не возвращать WebView, «Экономику», демо-данные, тексты разработчика, внешнюю авторизацию или вымышленную синхронизацию.

## P0 — первое открытие (Android, не HTML)

**Пути:** `android/app/src/main/AndroidManifest.xml`, `SplashActivity.java`, `IntroActivity.java`, `res/drawable/*`.

1. **Splash:** `SplashActivity` — launcher. Неперегруженная чёрно-зелёная заставка с узнаваемым знаком, названием «Расчёт», коротким мягким fade/scale, длительностью около 0.8 сек. На каждом запуске из launcher; одноразовое продолжение без повторных переходов при смене ориентации/возврате. Учитывать уменьшенную анимацию; никаких сетевых запросов.
2. **Onboarding:** три нативных экрана:
   - «Записывайте долги быстро» — создать клиента и зафиксировать долг.
   - «Принимайте оплаты без путаницы» — частичная и полная оплата с автоматическим остатком.
   - «Ваша книга всегда под рукой» — данные на устройстве, резервная JSON-копия.
   Прогресс 1/3…3/3, кнопки «Далее» / «Начать работу», «Пропустить», Back возвращает шаг. Состояние `completed` записывать только по явному завершению/пропуску, а не при показе; хранить в private SharedPreferences. При повороте не терять шаг. При повторном открытии переход сразу в книгу после splash.
3. **Первое действие:** если клиентов нет — после onboarding открыть «Клиенты» с понятной кнопкой создания. Если БД уже заполнена — обычный «Обзор». Пропуск не создаёт демонстрационные данные.

## P1 — нижняя навигация и читабельность

**Путь:** `MainActivity.java` (`createShell`, `render`).

- Высота телефонной нижней панели не менее **84–88dp** + системные безопасные отступы.
- Иконка 23–24dp; подпись 11–12sp, **одна строка без обрезания**, минимум 48dp по высоте для касания, правильное центрирование. Активный пункт — неброская подложка; сохранять TalkBack-название и selected state.
- Проверить экран 360dp, увеличенный системный шрифт, жестовую навигацию. На планшете оставить sidebar.

## P1 — пустые состояния

**Путь:** `MainActivity.java` (`fillClients`, `historyView`).

- Нет клиентов: тематическая иконка, «Пока нет клиентов», короткое объяснение, рабочая кнопка **«Добавить первого клиента»**.
- Поиск без совпадений: «Никого не нашли», предложение изменить запрос; не подменять ситуацию «вообще нет клиентов».
- История полностью пустая: «История пока пустая», объяснение и кнопка **«Записать долг»** (при отсутствии клиентов — создать клиента). Фильтр без записей: объяснение, **не маскировать его как глобальную пустую книгу**.

## P2 — компоновка и настройки

**Путь:** `MainActivity.java` (`homeView`, `settingsView`, `screen`).

- Уменьшить внутренние отступы главного hero и карт, удержать сумму главным акцентом.
- Сохранять обе операции «Записать долг» и «Принять оплату»: при узкой ширине/увеличенном системном шрифте располагать вертикально, иначе в ряд.
- Сократить заголовки/лишние вертикальные интервалы; не скрывать реальные цифры.
- «Крупный текст» — доступный нативный `Switch`, состояние сохраняется в текущих preferences, настройка применяется без перезапуска.
- Предупреждение о незашифрованных резервных копиях **не удалять**; отобразить компактно.

## Проверка/приёмка

1. **CI:** `node --test tests/ledger.test.js tests/android-bundle.test.js tests/android-onboarding.test.js`, затем `gradle -p android lintDebug assembleDebug --no-daemon`. APK существует, не содержит HTML/JS/веб-страницы, пакет не изменился.
2. **Runtime:** в эмуляторе или на Android 15/Legion Y70: свежая установка -> splash -> экран 1/3 -> 2/3 -> 3/3 -> «Начать работу» -> пустые «Клиенты»; первый клиент/долг/оплата -> остаток; закрыть/запустить снова -> splash -> без onboarding; Back и «Пропустить»; повернуть экран на шаге 2; bottom nav подписи видны целиком.
3. **Данные:** обновление с 0.3.1 не очищает SQLite/SharedPreferences; старая 0.2 (WebView) остаётся отдельным приложением, перенос только через JSON и подтверждение.
4. **Сигналы отказа:** нет реального запуска на эмуляторе -> не утверждать UI PASS. CI-компиляция не равна проверке экрана на телефоне.

## Изменение UX: фирменное знакомство Ventry (23.11.2026)
Сохранив три урока знакомства и статус их одноразового прохождения, добавлено первое приветственное окно Ventry. В нём реальный фирменный знак, позиционирование из репозитория Ventry и назначение продукта «Расчёт» как автономной долговой книги. Состав: Ventry 1/4 (с раскрываемым списком функций) → запись долга 2/4 → оплата 3/4 → резервная JSON-копия 4/4. На уроках отображается счётчик 1–3 из 3. Кнопка первого экрана «Как это работает», пропуск и Back сохранены; состояние раскрытия выдерживает поворот. Старые `SharedPreferences` и `LedgerStore` не изменяются.
