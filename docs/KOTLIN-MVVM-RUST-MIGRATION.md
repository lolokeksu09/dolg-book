# Расчёт — Kotlin, MVVM и Rust

Работы по архитектуре ведутся в E-05 общего плана. Фактическая ревизия и следующая задача указаны в [точке продолжения](CONTINUATION.md).

## Текущие границы

| Слой | Ответственность |
|---|---|
| Compose и `MainActivity.java` | Compose отображает основные экраны. Activity связывает навигацию, жизненный цикл и часть диалогов, состояния и SAF. |
| `BookViewModel` и `AnalyticsViewModel` | Наблюдаемое состояние книги, команды записи и запросы статистики. |
| `LedgerRepository` и `LedgerStore` | Снимок SQLite, транзакции записи и атомарный импорт. SQLite хранит схему версии 4. |
| `CorrectionEngine` и Rust JNI | Нативный расчёт исправления в release и при включённом Rust preview. Репозиторий и SQLite сохраняют ответственность за транзакцию и повторную валидацию. |
| Kotlin domain | Денежная арифметика, проекции, отчёты и валидация импорта. Наличие Rust-реализации проекции само по себе не подключает её к APK. |

## Инварианты при переносе

- Сохранять идентификаторы приложения, подпись, Android API 26, четыре ABI release, старые SQLite-книги и поддерживаемые версии JSON.
- Хранить деньги целыми копейками в `Long`, предел суммы операции и остатка — `100_000_000_000` копеек. Исправление записывает отмену и замену атомарно. Сохранять ID операций и порядок записи.
- FIFO использует существующий порядок операций. Сроки работают по локальным датам, исторические оплаты проверяются на выбранный день, обещания опираются на активные записи. Перенос проверяется на одних и тех же сценариях Kotlin, Rust и SQLite.
- Импорт создаёт защищённую точку перед изменением книги. Покрытие JSON, локальных настроек и облачных копий описывается отдельно. При ошибке JNI результат исправления не записывается.

Продолжать выделение по завершённым сценариям. Проверять восстановление состояния, возврат из SAF и старую книгу после обновления. Использовать [порядок приёмки Android](RASCHET-ACCEPTANCE.md) и [проверки Rust JNI](RASCHET-RUST-RELEASE-REFACTOR.md).
