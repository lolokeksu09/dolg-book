# Долговая книга: история обещаний оплаты

Зависимость: PR #26 (рабочая очередь возврата). Область: Android, без передачи долговых данных на VDS.

## Контракт
- SQLite schema v4 добавляет collection_plans. Каждая запись — интервал одного согласованного обещания или контакта. Платежи остаются в entries, план никогда не изменяет баланс. Замена/удаление закрывает предыдущий интервал по последнему ID операции. Новый отсчёт начинается после него. Одно активное обещание/контакт на клиента. При изменении даты/комментария и сохранении суммы сохраняются исходный срок и интервал; это обновление согласованного срока, не отдельное денежное обещание. Закрытые интервалы не переписываются.
- Записи планов создаются в том же сериализованном IO-контуре ClientCommand и транзакции SQLite с проверкой ожидаемого ID. Изменение из устаревшей формы отклоняется. Полное погашение закрывает только план контакта, а денежное обещание остаётся доступным в истории.
- Миграция 1–3 → 4 сохраняет все финансовые записи и импортирует существующие локальные планы реальной базы один раз. Неизвестная дата создания остаётся неизвестной. Отсутствующий/чужой исходный ID мигрирует как "Требуется проверка"; отсутствующая старая история не выдумывается.
- JSON v5 содержит products и plans, только если история присутствует. Старые v1–v4 сохраняют поддержку. Восстановление v5 валидирует клиентов, идентификаторы, ссылки на операции, одну открытую запись и отсутствие пересечения интервалов до общего commit. Планы входят и в защищённые точки восстановления. Импорт старой копии не восстанавливает отсутствующую историю; действующая перед импортом книга сохраняется обычным механизмом pre-restore. Старые APK не умеют импортировать v5 и не должны использоваться для отката SQLite v4.
- Текущие планы и финансовые записи читаются одним LedgerSnapshot, общий расчёт и история используют одинаковый принцип отменённых операций. В отчёте учитываются только денежные обещания, в том числе погашенных клиентов. Период 7/30/90 дней — по последнему согласованному сроку; "Все сроки" включает будущие. Суммы ограничены обещанной суммой каждого интервала, пропуски ссылок исключены из суммы. Операции, отменённые после закрытия плана, корректируют отображаемую историю; это не неизменяемый фискальный отчёт. Для оценки оплаты в срок используется дата операции, включая датированные платежи, а не момент их ввода.
- Вкладка "Возврат долгов" открывает историю, поиск по имени, сводку исполненных в срок/поздно, пропущенных, закрытых до срока, ожидающих и требующих проверки. Никаких новых коммерческих условий или отдельного платного модуля.

## Приёмка
Instrumented тест PromiseHistoryInstrumentedTest: миграция старой схемы, невалидный legacy anchor, проверка повтора миграции, v5 roundtrip, откат повреждённого/пересекающегося импорта, устаревшая форма, отмена оплаты, восстановление v2. Существующий BookCollectionsComposeTest расширен проверкой входа в историю и периода. Новые проверки добавлены после реализации; тестовый порядок не является TDD. Реальный релиз требует успешного CI и безопасного обновления/проверки APK.
