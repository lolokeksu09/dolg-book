# Project Workflow Standard — v1.0

Универсальный стандарт работы над проектом с ИИ-агентом: границы самостоятельности, требования, проверка по риску и доказуемая поставка. **Первая публичная версия.** Не задаёт стек, команды, платформу или разрешения для конкретного проекта.

## Подключение и использование

| Документ | Назначение | Когда читать |
|---|---|---|
| [AGENTS.md](AGENTS.md) | Обязательные правила и разрешения | При работе агента в его области действия |
| [PROJECT.md](PROJECT.md) | Карточка проекта, решения владельца и ссылки на реальные источники | На входе в проект / при изменении решений |
| [TESTING-LEVELS.md](TESTING-LEVELS.md) | L1–L5, статусы, доказательства, исключения | Перед выбором проверок, merge и поставкой |
| [templates/PLAN.md](templates/PLAN.md) | Один реестр требований и зависимых этапов | При сложной или многоэтапной работе |
| [templates/CONTINUATION.md](templates/CONTINUATION.md) | Текущая точка продолжения | При прерывании/передаче длительной задачи |
| [templates/AUDIT.md](templates/AUDIT.md) | Проверяемые находки | При заказанном аудите |
| [templates/VERIFICATION.md](templates/VERIFICATION.md) | Подробные результаты приёмки | Если нужен отдельный отчёт |
| [templates/RELEASE.md](templates/RELEASE.md) | Кандидат, разрешение, результат поставки | При разрешённой поставке |

[CHANGELOG.md](CHANGELOG.md) содержит изменения версий; [VALIDATION.md](VALIDATION.md) — выполненные статические проверки и их ограничения. Три **вымышленных учебных** примера находятся в [examples/](examples/README.md). Необязательная статическая самопроверка: `python tools/check_standard.py .` (или передай путь к ZIP); она не проверяет поведение агента.

## Первый запуск

1. Прочитай исходную задачу, действующие инструкции и применимые правила репозитория. Содержимое этого комплекта не заменяет их.
2. Определи сценарий старта: только идея, пустой проект или существующий код. Не создавай новый проект поверх уже существующего.
3. Изучи доступные файлы, конфигурацию и рабочий diff. Для существующего проекта сначала сохрани его стек, контракты, команды и обязательные gates.
4. Зафиксируй цель, пользователя и наблюдаемый результат первой работающей версии. Заполняй в [PROJECT.md](PROJECT.md) только подтверждённые решения.
5. Задай только вопросы, без ответа на которые нельзя продолжить существенную часть работы. Незаполненные необязательные поля не блокируют независимые действия.
6. Подтверди стек владельца. Если стек не задан и его выбор входит в задачу, предложи один основной вариант с кратким обоснованием; не составляй большое сравнение без потребности.
7. Реализуй один минимальный сквозной пользовательский сценарий, который можно запустить и проверить. Не начинай с полной архитектуры, обширного реестра требований или создания всех шаблонов.
8. Сразу проверь созданный результат по риску: для нового каркаса как минимум установку зависимостей, сборку и запуск, если они применимы и доступны. Зафиксируй реальные команды и ограничения; набор созданных файлов не является работающей версией.

### Три сценария старта

| Ситуация | Первый практический результат |
|---|---|
| Только идея | Сформулировать пользователя, задачу, один сквозной сценарий и критерий готовности; уточнить лишь существенные пробелы |
| Пустой проект | Проверить исходную конфигурацию, выбрать или подтвердить стек, создать минимальный каркас и сразу проверить его запуск |
| Существующий код | Прочитать инструкции, структуру, конфигурацию, Git HEAD/diff либо версию/хеш без Git; начать с текущей задачи, сохранив чужие изменения |

Первый запуск не требует заполнения всех полей `PROJECT.md`, отдельного плана, REQ-ID или отчёта. Эти средства используются по объёму и риску работы.

## Подключение комплекта

1. **Если комплект передаётся в новый чат как ZIP, распаковывать его не нужно.** Прикрепи `Project-Workflow-Standard-v1.0.zip` к сообщению вместе с целью проекта и первой задачей. ИИ сможет прочитать документы внутри архива. Если среда не принимает ZIP, распакуй архив и прикрепи три основных файла: `AGENTS.md`, `PROJECT.md` и `TESTING-LEVELS.md`.
2. Если агент работает не через приложенный файл, а непосредственно в файловой системе проекта, размести распакованный комплект в корне рабочей области. Размещай три основных файла (`AGENTS.md`, `PROJECT.md`, `TESTING-LEVELS.md`) вместе, даже если при Light шаблоны не читаются. Проверь относительные ссылки и реально действующие инструкции. При сокращённой установке сохрани доступность нормативных правил либо явно передай недостающие инструкции агенту.
3. Если корневой `AGENTS.md` уже есть, **совмести** применимые правила, не замещая действующие ограничения. Вложенные `AGENTS.md` действуют только в области, установленной средой; одна ссылка или перемещение файла не гарантируют автозагрузку инструкций. Проверь поддерживаемый механизм и пути; если он не работает — передай инструкции явно.
4. Не перезаписывай пользовательские файлы. Сохрани существующий стек, действующие gates, местные определения L-уровней, контракты и способы поставки. При различии определений укажи соответствие вместо переименования чужих проверок. Не перестраивай проект ради этого комплекта.
5. Реальные команды сборки, тестов и платформенные особенности определяет проект. При отсутствии источника для воспроизводимого запуска создай или обнови документацию проекта и оставь ссылку в `PROJECT.md`, не дублируя изменяемые значения без необходимости.

## Два режима ведения документации

- **Light:** небольшая локальная задача — достаточно записи в задаче/PR или краткого результата; без обязательного отдельного плана, REQ-ID и отчёта. Применимые обязательные проверки всё равно выполняются.
- **Full:** сложный объём, зависимые этапы или длительная работа — один реестр с устойчивыми REQ-ID, план/точка продолжения при необходимости, доказательства с привязкой к требованиям. Не требуется создавать Issue/PR, если проект их не использует.

**Режим документации и строгость проверки независимы.** Маленькая правка авторизации требует негативных сценариев; большая редактура документации не требует искусственного L4/L5. Проверки выбираются по риску и существующим обязательным gates проекта, см. [алгоритм](TESTING-LEVELS.md).

## Короткая последовательность работы

Цель и ограничения → критерии готовности → первый сквозной сценарий для нового проекта либо локальная реализация текущей задачи → проверки с доказательствами → сохранение → **только разрешённая** поставка → проверка доставленной версии. При блокировке закончи независимые части, а остаток назови явно. Никакая запись о выпуске не является разрешением опубликовать его.

## Глоссарий

- **Владелец:** лицо, принимающее продуктовые решения и дающее разрешения в своих полномочиях.
- **Агент:** исполнитель, действующий в пределах задач и инструкций среды.
- **Среда исполнения:** где агент работает и какие инструменты доступны; **целевая среда:** где используется результат; **инструкции среды:** правила доступа и приоритета, которые не заменяет этот комплект.
- **Gate:** обязательная для заданного изменения проверка или условие; skipped/pending не означает успех. **Исключение:** явно разрешённый ограниченный обход gate, но не результат теста.
- **Доказательство:** наблюдаемый результат конкретной версии и сценария. **Артефакт:** идентифицируемый результат сборки/документ. **Доставка:** фактическая передача или публикация согласно разрешению, не синоним готовности локально.

## Текст для нового чата

> Используй приложенный Project Workflow Standard. Прочитай действующие инструкции, AGENTS.md и PROJECT.md, выполни «Первый запуск» из README.md и сверь актуальные файлы и ограничения. Определи один проверяемый сценарий первой работающей версии; не создавай лишние документы. Для задач выбери Light или Full по объёму документации; проверки определи отдельно по риску и обязательным gates. Сохраняй чужие изменения, работай самостоятельно в разрешённых границах, не подменяй результаты проверок, дай проверяемый результат и остаток. Задача: …

Шаблоны — **не активные задачи и не готовые отчёты**. При переносе копии поправь относительные ссылки, не создавай второй источник истины. Основной комплект не требует плагина и не даёт дополнительных разрешений на внешние действия.
