# Закрытый пилот на VDS

Пилот рассчитан на синтетические данные и два аккаунта. Keycloak, PostgreSQL и книга запускаются отдельным Compose-проектом. Caddy обслуживает две новые HTTPS-точки входа на существующих портах. Контейнеры пилота не публикуют отдельные порты. Суммарные лимиты контейнеров — 1252 МиБ. Нагрузка на реальном VDS проверяется после запуска.

Скрипт проверяет адреса DNS, состояние Ventry и текущий Caddyfile, затем сохраняет копию Caddyfile перед изменением. При сбое применения или первичной проверки маршруты откатываются. Каталог `/opt/raschet-pilot/state` доступен root. Он содержит тестовые пароли и серверные секреты. Данные книги и Keycloak сохраняются в Docker volumes.

Из каталога проверенного checkout:

```sh
bash deploy/pilot/run.sh start
```

Успешная HTTP-проверка выводит `PILOT_READY`. Прочитайте пароли на VDS командой `cat /opt/raschet-pilot/state/accounts.txt`. Проверьте вход в книге под `buyer`, создайте вымышленный магазин и подтвердите вымышленную оплату под `operator` через админку. После этого проверьте запись долга и частичную оплату. Пароли не передаются в чат.

Чтобы остановить пилот и убрать его маршруты из Caddy, выполните `bash deploy/pilot/run.sh stop`. Тома и учётные данные сохраняются. Повторный запуск использует существующее состояние. Обновление Ventry может заменить Caddyfile и изменить IP Caddy. После такого обновления повторите `run.sh start`, чтобы восстановить маршруты и обновить адрес доверенного прокси.

Для реальных данных нужны проверка устойчивости VDS, резервные копии с проверенным восстановлением и отдельная настройка эксплуатации. Этот скрипт не предназначен для такого запуска.
